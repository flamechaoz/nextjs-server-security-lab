## What you'll learn

- Choose the correct status for common failures.
- Separate expected errors from unexpected exceptions.
- Avoid leaking stack traces.

### Expected failures are part of the API

Invalid input, missing records, and permission failures are normal outcomes. Handle them explicitly and return stable error shapes.

### Do not expose internals

Unexpected exceptions should be logged appropriately on the server while clients receive a generic message and a correlation identifier when available.

## Walkthrough

1. Inspect the error responses in the task routes.
2. Try malformed JSON, invalid IDs, and unknown IDs.
3. Compare status codes and response shapes.
4. Check that internal stack traces are not returned.
