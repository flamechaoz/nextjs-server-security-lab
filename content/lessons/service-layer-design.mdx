## What you'll learn

- Explain the route/service/repository boundary.
- Keep validation and business rules explicit.
- Make logic easy to test without HTTP.

### Thin route handlers

Route handlers translate HTTP into application calls and application results back into HTTP. Business rules should live in focused functions that can be tested directly.

### Storage can change

An in-memory store is useful for teaching, but a production system should use persistent storage and account for concurrent updates.

## Walkthrough

1. Open lib/services/task-service.ts.
2. Compare its functions with app/api/tasks/route.ts.
3. Identify which code knows about HTTP and which code knows task rules.
4. Add a focused service function rather than duplicating logic in a route.
