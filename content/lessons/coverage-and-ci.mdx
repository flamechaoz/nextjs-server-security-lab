## What you'll learn

- Generate a coverage report.
- Understand statements, branches, functions, and lines.
- Automate tests, lint, and type checking.

### Coverage is a map, not a grade

Coverage shows which code executed during tests. It does not prove assertions are meaningful or that all security scenarios are covered.

### Repeatable quality gates

CI should run the same predictable checks developers can run locally: lint, type checking, tests, and production build where appropriate.

## Walkthrough

1. Run npm run test:coverage.
2. Inspect uncovered branches in the report.
3. Add tests for meaningful uncovered failure paths.
4. Run npm run lint and npm run typecheck.

### Code walkthrough: `package.json`

```tsx
"scripts": {
  "test": "jest --runInBand",
  "test:coverage": "jest --coverage --runInBand",
  "lint": "eslint .",
  "typecheck": "tsc --noEmit"
}
```
