## What you'll learn

- Identify common trust-boundary failures.
- Use safe rendering and parameterized data access.
- Choose suitable request and origin protections.
- Recognize and prevent open redirects without navigating to an untrusted destination.

### Treat input as hostile

Validate input at the boundary, use safe rendering, avoid unsafe HTML injection, and use parameterized database operations. Validation should complement—not replace—safe APIs.

### Browser requests have security context

Cookie-authenticated state changes need a CSRF strategy. A browser can attach a user's cookies to a request initiated by another site, so authentication alone does not prove that the user intended the action. `SameSite` cookies are useful defense in depth, but they do not replace an explicit policy for state-changing requests. CORS controls whether browser code can read a response; it is not authentication and does not stop every cross-origin request.

### Code walkthrough: protect a cookie-authenticated mutation

For a browser-only mutation endpoint, await Next.js's asynchronous `cookies()` API, validate the session, and compare the complete request `Origin` to the configured trusted origin. Reject missing or unexpected origins before performing any state change:

```ts
import { cookies } from "next/headers";
import {
  DEMO_SESSION_COOKIE,
  getDemoSession,
} from "@/lib/demo-session";

export async function POST(request: Request) {
  const trustedOrigin = process.env.APP_ORIGIN;
  if (!trustedOrigin || request.headers.get("origin") !== trustedOrigin) {
    return Response.json({ error: "Forbidden" }, { status: 403 });
  }

  const cookieStore = await cookies();
  const authCookie = cookieStore.get(DEMO_SESSION_COOKIE);
  const session = getDemoSession(authCookie?.value);
  if (!session) {
    return Response.json({ error: "Unauthorized" }, { status: 401 });
  }

  const formData = await request.formData();
  const displayName = formData.get("displayName");
  if (typeof displayName !== "string" || displayName.trim().length === 0) {
    return Response.json({ error: "Invalid input" }, { status: 400 });
  }
  // Perform the authorized state change only after these checks.
  return Response.json({ ok: true });
}
```

Set `APP_ORIGIN` to the application's exact public origin, such as `https://app.example.com` (no trailing slash). This example intentionally rejects requests without an `Origin`; applications that support clients that omit it should choose and test an explicit alternative, such as a synchronizer token. An Origin check does not protect against same-origin script injection, so XSS defenses still matter.
