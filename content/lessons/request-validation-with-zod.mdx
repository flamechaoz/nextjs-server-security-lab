## What you'll learn

- Treat request bodies as untrusted input.
- Validate with safeParse.
- Return useful errors without accepting invalid data.

### Types do not validate runtime input

TypeScript types disappear at runtime. JSON received over HTTP must be validated before business logic trusts it.

### safeParse makes failure explicit

Zod's safeParse returns a success result or structured validation errors without requiring exceptions for expected invalid input.

## Walkthrough

1. Open lib/validation/task-schema.ts.
2. Inspect the schema constraints.
3. Follow the POST handler from request.json to safeParse.
4. Try an empty title and an invalid completed value.

### Code walkthrough: `lib/validation/task-schema.ts`

```tsx
import { z } from "zod";

export const createTaskSchema = z.object({
  title: z.string().trim().min(1).max(120),
});

const result = createTaskSchema.safeParse(input);
if (!result.success) {
  // Return HTTP 400; do not persist input.
}
```
