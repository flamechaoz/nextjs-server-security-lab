## What you'll learn

- Implement a complete protected API flow.
- Demonstrate authorization and validation with tests.
- Explain the release readiness of the solution.

### Security is end-to-end

A secure API needs multiple controls working together: validated input, verified identity, resource-level authorization, safe errors, and regression tests.

### A release is evidence

A production-ready change is not just code that works locally. It includes tests, type checks, quality checks, operational considerations, and a clear explanation of limitations.

## Walkthrough

1. Review the task CRUD routes and service layer.
2. Ensure all inputs are validated.
3. Verify authentication and ownership checks for protected actions.
4. Add success, invalid input, not-found, and denied-access tests.
5. Run lint, typecheck, tests, and build.
6. Document limitations of the in-memory teaching store.
