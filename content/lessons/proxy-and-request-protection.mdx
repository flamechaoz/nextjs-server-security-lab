## What you'll learn

- Explain the purpose of Proxy.
- Match paths intentionally.
- Keep authorization close to protected data.

### Proxy is an early gate

Proxy can perform lightweight redirects and request checks before a route continues. It is useful for coarse navigation and request policy.

### It is not the whole security model

A request may reach a handler through different paths or runtime contexts. Verify identity and permissions in the protected operation itself. Current Next.js versions use proxy.ts; older projects may use middleware.ts.

## Walkthrough

1. Inspect proxy.ts if present, or compare the middleware.ts convention for older versions.
2. Review which paths are matched.
3. Check that protected route handlers still verify access.
4. Avoid putting database-heavy authorization logic in a request interceptor.

### Code walkthrough: `proxy.ts`

```tsx
import { NextResponse, type NextRequest } from "next/server";

export function proxy(request: NextRequest) {
  // Lightweight routing decision only.
  return NextResponse.next();
}
```
