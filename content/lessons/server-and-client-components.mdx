## What you'll learn

- Describe Server Components and Client Components.
- Identify when state and event handlers require a client boundary.
- Avoid sending server-only values to the browser.

### Server by default

Components in the App Router are Server Components unless marked with the use client directive. They can read server-side resources and render HTML without shipping their implementation to the browser.

### Client for interaction

Use Client Components for state, effects, event handlers, and browser APIs. Put `"use client"` before imports in the client module and keep the boundary as small as practical. Server Components are the default in the App Router; they do not need a `"use server"` directive.

### Code walkthrough: `components/BoundaryCounter.tsx`

```tsx
"use client";

import { useState } from "react";

export function ExampleCounter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}
```
