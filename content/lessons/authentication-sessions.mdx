## What you'll learn

- Distinguish authentication from authorization.
- Explain secure session-cookie flags.
- Verify identity on the server for protected actions.

### Authentication answers who

A protected endpoint must establish the current identity from a trusted session or token. A user ID supplied in the request body is not proof of identity.

### Cookie protections

Session cookies commonly use HttpOnly, Secure in HTTPS deployments, and an appropriate SameSite policy. These attributes help but do not replace authorization or CSRF analysis.

## Walkthrough

1. Review the authentication boundary chosen for the project.
2. Identify how a protected route obtains the current user.
3. Check session expiration and cookie settings.
4. Ensure client-provided user IDs are never treated as proof of identity.
