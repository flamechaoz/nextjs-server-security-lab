## What you'll learn

- Recognize public environment variables.
- Keep secret-dependent modules on the server.
- Avoid logging or returning sensitive data.

### Public prefix means public

Next.js exposes NEXT_PUBLIC_ environment variables to browser code. Never use that prefix for private API tokens, database credentials, or signing secrets.

### Enforce the boundary

Use server-only modules and avoid importing secret-bearing code from Client Components. Only return the fields the client actually needs.

## Walkthrough

1. Review .env.example and local environment variable names.
2. Search imports from client components into server data modules.
3. Use server-only boundaries for sensitive services.
4. Inspect API responses and logs for accidental secret exposure.

### Code walkthrough: `.env.example`

```tsx
# Private server runtime value
UPSTREAM_API_TOKEN=replace-locally

# Public values are visible to browser code
NEXT_PUBLIC_APP_NAME=Next Lab
```
