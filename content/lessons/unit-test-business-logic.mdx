## What you'll learn

- Test pure business rules.
- Cover boundary and negative cases.
- Mock external dependencies selectively.

### Test behavior, not line count

A useful test suite covers meaningful inputs and outputs, including boundaries and failure cases. High line coverage alone does not prove the code is correct.

### Keep units isolated

Pure functions need no mocks. For services that use external systems, inject dependencies or mock the boundary rather than mocking every internal call.

## Walkthrough

1. Open lib/task-rules.test.ts and the validation schema tests.
2. Add empty, boundary, and invalid input cases.
3. Use clear test names that describe behavior.
4. Avoid dependence on test execution order.
