## What you'll learn

- Test pure functions with Arrange–Act–Assert.
- Isolate services that read or mutate state.
- Test custom hooks through their observable return values.

### Start with the unit boundary

A unit is the smallest behavior you can exercise with a useful, stable assertion. A pure function is usually the simplest unit: provide inputs, call it, and inspect the return value. A service may coordinate state or dependencies, so reset its state between tests and mock only external boundaries. A hook is a function whose behavior depends on React's hook runtime; render it with a hook test utility instead of calling it as an ordinary function.

### Test pure functions with AAA

Pure functions do not need a server, browser, or mock. Keep the setup, call, and assertion visible so a regression cannot hide behind a hard-coded value.

```tsx
it("rejects a different user", () => {
  // Arrange
  const userId = "user-2";
  const ownerId = "user-1";

  // Act
  const allowed = canEditTask(userId, ownerId);

  // Assert
  expect(allowed).toBe(false);
});
```

### Test services at their public boundary

Services often read a repository, mutate in-memory state, or coordinate several operations. Test the service's public result rather than its private implementation. Reset shared state in `beforeEach()` so one test cannot change the next test's result.

```tsx
beforeEach(() => {
  resetTasksForTests();
});

it("lists tasks for one owner", () => {
  // Arrange
  createTask("Private task", "user-2");

  // Act
  const tasks = listTasks("user-1");

  // Assert
  expect(tasks).toHaveLength(3);
  expect(tasks.every((task) => task.ownerId === "user-1")).toBe(true);
});
```

When a service depends on a database, network client, or clock, inject that dependency and mock the boundary. Do not mock the service method you are trying to test.

### Test hooks through rendered behavior

Custom hooks must run inside React's hook environment. Testing Library's `renderHook` provides that environment and exposes the hook's current result. Assert the returned value or state transition, not the hook's private variables or React internals.

```tsx
it("trims a task label", () => {
  const { result } = renderHook(() => useTaskLabel("  Secure task  "));

  expect(result.current).toBe("Secure task");
});
```

For hooks that update state, use `act()` around the interaction that triggers the update, then assert the new result. If the hook is only a thin wrapper around a pure function, keep the pure-function tests separate and use the hook test for the React-specific behavior.

### Test behavior, not line count

A useful suite covers meaningful inputs, boundaries, negative cases, and state transitions. High line coverage alone does not prove that a pure function, service, or hook is correct.
